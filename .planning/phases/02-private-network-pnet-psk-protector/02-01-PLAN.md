<objective>
Vendor a self-contained XSalsa20 stream cipher as the cryptographic primitive for the pnet layer (Phase 2, requirement PNET-02), validated against published libsodium/Go test vectors per D-03.

Purpose: The libp2p pnet spec v1 mandates XSalsa20 (256-bit key, 24-byte nonce, no MAC). OpenSSL does not implement XSalsa20 and D-01 locks the decision to vendor a small public-domain implementation (~150-250 lines) rather than adding libsodium/Crypto++ via Hunter — eliminating the MSVC/Hunter packaging risk flagged in STATE.md as a phase blocker. This plan is the foundation Plan 03 (`PnetProtectedConnection`) builds directly on.

Output: `p2p_crypto_xsalsa20` leaf library exposing free functions + a stateful stream type in `libp2p::crypto::xsalsa20` (D-02), plus a known-answer test target `xsalsa20_test`.
</objective>

Implement the vendored cipher per D-01 (no libsodium, no Crypto++, no Hunter addition). Public surface in namespace libp2p::crypto::xsalsa20, header guard LIBP2P_CRYPTO_XSALSA20_XSALSA20_HPP:

- Constants: kKeySize = 32, kNonceSize = 24, and the sigma constant "expand 32-byte k" (16 bytes) — internal detail.
- `class XSalsa20Stream` — stateful keystream type. Constructor takes key (gsl::span<const uint8_t>, exactly 32 bytes) + nonce (exactly 24 bytes); derives the HSalsa20 subkey from key+nonce[0..16), then runs the Salsa20/20 core keyed with the subkey from counter 0 using nonce[16..24) as the 8-byte stream nonce (libsodium crypto_stream_xsalsa20 semantics). Method `void crypt(gsl::span<uint8_t> in_out)` — in-place XOR of the keystream (encrypt and decrypt are the same operation, never expose separate paths). Internals: 64-bit block counter + a leftover-bytes buffer so that ANY length advances the position by exactly that length (RESEARCH Pitfall 1 — the #1 vendoring bug source; equivalent to libsodium's crypto_stream_xsalsa20_xor_ic incremental behavior). Keep the core rounds/subkey code in an anonymous or detail namespace per .planning conventions.
- Free function `outcome::result<std::vector<uint8_t>> xsalsa20(key, nonce, message)` — one-shot convenience (fresh stream internally), mirroring the free-function-next-to-class layout of sha256.hpp.
- `outcome::result<std::array<uint8_t, kNonceSize>> generateNonce()` — calls OpenSSL RAND_bytes directly (D-04: OpenSSL RAND_bytes is the locked decision for the 24-byte nonce; go-libp2p uses the platform CSPRNG equivalently). Returns error outcome if RAND_bytes fails.
- Low-ceremony per D-02: no provider interface, no DI binding, no virtuals.
