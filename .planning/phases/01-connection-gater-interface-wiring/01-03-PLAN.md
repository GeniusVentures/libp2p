| Remote peer (post-handshake) -> local host | interceptSecured/interceptUpgraded are the last 2 checkpoints before an authenticated, muxed connection is handed to the application layer |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-------------------|
| T-01-07 | Denial of Service | UpgraderSession rejection teardown | high | mitigate | GATE-05: every rejection closes the relevant SecureConnection/CapableConnection guarded by !isClosed(), preventing leaked sockets on repeated rejected-then-retried connections |
| T-01-08 | Tampering (reentrancy) | onSecured() / upgradeToMuxed completion lambda | high | mitigate | handler_ is only ever invoked synchronously for the pre-existing non-gater error path; every gater-rejection-triggered handler_ call is deferred via scheduler_->schedule(...), matching the codebase's documented TODO(107) reentrancy-avoidance convention |
| T-01-09 | Repudiation | Rejection observability | low | mitigate | D-06: both interceptSecured/interceptUpgraded rejections are logged via SL_DEBUG with remote peer id and address where available |
</threat_model>
