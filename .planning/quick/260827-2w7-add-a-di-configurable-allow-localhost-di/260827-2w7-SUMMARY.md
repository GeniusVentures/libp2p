# Quick Task 260827-2w7: DI-configurable allow-loopback-dial Summary

**Restored TcpTransport's secure-by-default loopback-dial rejection behind a new PskHandle-shaped `AllowLoopbackDial` DI type, opt-in via `injector::useAllowLoopbackDial()` -- closing 03-UAT.md's pending SSRF-style safety-control gap without re-breaking `pnet_two_node_test`'s live two-node dialing.**

## Performance

- **Completed:** 2026-08-27T06:21:19Z
- **Tasks:** 3
- **Files modified:** 6 (1 created, 5 modified)

## Accomplishments
- Restored `TcpTransport::dial()`'s `isLocalHost(...)` -> `bad_address` loopback rejection in both overloads, matching the pre-78de11e shape, gated behind a new `AllowLoopbackDial` DI value type (PskHandle-precedent: explicit non-aggregate constructors)
- Added `injector::useAllowLoopbackDial()` opt-in helper and a false-by-default baseline binding in `makeNetworkInjector`, so `TcpTransport`'s new ctor parameter always resolves through the DI graph
- Opted `pnet_two_node_test.cpp`'s `makeNode<Marker>()` into `useAllowLoopbackDial()`, since that fixture's whole purpose is live loopback TCP dialing between DI-assembled Hosts
- Confirmed (structurally via `dialer_impl.cpp` grep, and empirically via smoke-run output) that `example/05-private-network`, `example/06-private-network-gater`, `example/07-connection-gater` need no source changes -- 05 never dials, and 06/07's denylisted-peer self-dial is rejected at `DialerImpl::interceptPeerDial` before `TransportAdaptor::dial()` is ever invoked
- Resolved `.planning/phases/03-hardening-live-validation-documentation/03-UAT.md` test 1: `result: pass`, `status: resolved`, Summary `passed: 1 / pending: 0`

## Decisions Made
- `AllowLoopbackDial` mirrors `PskHandle`'s non-aggregate-ctor shape (explicit `bool` ctor, defaulted default ctor) so Boost.DI never falls back to aggregate-member auto-injection on a default-valued ctor parameter.
- Restored guard uses `std::errc::bad_address` (the code present immediately before 78de11e's removal), not the earlier, superseded `address_family_not_supported` from 3d61147.
- Baseline (`allow=false`) `AllowLoopbackDial` binding placed in `makeNetworkInjector`'s `di::make_injector` call immediately before the `TransportAdaptor -> TcpTransport` binding, mirroring `PskHandle`'s existing baseline-binding comment/pattern.
