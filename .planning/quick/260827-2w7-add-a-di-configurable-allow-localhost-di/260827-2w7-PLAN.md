<objective>
Restore TcpTransport's secure-by-default loopback-dial rejection (removed in 78de11e to unblock Phase 3's live two-node pnet test), but make it DI-configurable per the maintainer's decision: a new Boost.DI-injectable `AllowLoopbackDial` value type (following the `PskHandle` precedent -- explicit non-aggregate constructors, not a bare `bool` ctor param) gates `TcpTransport::dial()`'s `isLocalHost(...)` guard in both overloads. Defaults to false (reject) when not explicitly bound. A new `injector::useAllowLoopbackDial()` DI helper, matching the `usePrivateNetwork(key)` / `useConnectionGater&lt;GaterImpl&gt;()` naming convention, lets integrators opt in. `pnet_two_node_test.cpp` -- the one real caller that legitimately needs live loopback dialing -- is updated to opt in explicitly. This resolves the open human-verification item (test 1) in `.planning/phases/03-hardening-live-validation-documentation/03-UAT.md`.

Purpose: Close 03-UAT.md's pending SSRF-style safety-control gap without reintroducing the original unconditional block that broke the live pnet acceptance test.
Output: `AllowLoopbackDial` DI type, restored+gated guard in `TcpTransport::dial()`, `useAllowLoopbackDial()` injector helper, updated `pnet_two_node_test.cpp`, resolved `03-UAT.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Remote peer's advertised `PeerInfo`/multiaddresses -&gt; this node's outbound TCP dial target | A malicious or compromised peer can advertise arbitrary addresses (including this node's own loopback-bound services) in the addresses this node uses to dial it |
| Integrator's DI injector composition -&gt; TcpTransport's runtime dial policy | Whether loopback dialing is permitted is now a single opt-in DI binding call, not a compile-time constant -- an integrator's injector wiring determines the effective security posture |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-quick-01 | Spoofing / SSRF | TcpTransport::dial() (both overloads), src/transport/tcp/tcp_transport.cpp | high | mitigate | Restore the isLocalHost(...)-&gt;bad_address rejection removed in 78de11e; a remote peer's PeerInfo can never induce this node to dial 127.0.0.0/8 or ::1 unless the integrator has explicitly called injector::useAllowLoopbackDial() -- secure by default (D: maintainer decision, this task) |
| T-quick-02 | Elevation of Privilege | injector::useAllowLoopbackDial(), include/libp2p/injector/network_injector.hpp | medium | accept | A single, explicit, discoverable opt-in call site (same shape as usePrivateNetwork()/useConnectionGater&lt;T&gt;()); Doxygen-documented as loosening the loopback guard; an integrator who calls it in a production composition has made a deliberate, visible choice, not an accidental one -- accepted risk, consistent with how this project already treats useConnectionGater&lt;PermissiveConnectionGater&gt; as an explicit opt-out of the default posture |
</threat_model>
